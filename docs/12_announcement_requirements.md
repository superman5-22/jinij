## 1. 目的・背景

### 1.1 背景

jinij 人事システムは従業員管理・休暇申請・勤怠・給与・人事評価など
HR 業務を一元管理するシステムである。  
しかし、HR 担当者や管理者が全社員へ向けた情報（制度改定・システムメンテナンス・健康診断
案内など）を発信する手段が存在しなかった。社員はメールや口頭で情報を受け取っていたため、
伝達漏れや情報格差が発生していた。

### 1.2 目的

本機能は、**HR 担当者・管理者が全社員向けのお知らせを作成・公開し、
社員が人事システム上で確認できる仕組みを提供する**ことを目的とする。

これにより次の課題を解消する：

- 重要情報の伝達漏れ防止
- 情報発信の一元化（人事システム内での完結）
- 優先度・カテゴリによる情報整理
- 有効期限管理による古い情報の自動非表示

## 2. 対象ユーザー・利用シーン

### 2.1 対象ユーザー

| ロール | 権限 | 主な利用シーン |
|-------|------|--------------|
| admin（管理者）| 作成・編集・削除・公開切替・閲覧（全件） | 経営方針・制度改定の告知 |
| hr（人事担当） | 作成・編集・削除・公開切替・閲覧（全件） | 健康診断・休暇制度案内 |
| manager（マネージャー） | 閲覧（公開中のみ） | 社内情報の確認 |
| employee（従業員） | 閲覧（公開中のみ） | 社内情報の確認 |

### 2.2 利用シーン例

- HR 担当者が夏季休暇のお知らせを事前に作成し、公開日を設定して自動公開する
- IT 担当がシステムメンテナンスの緊急告知を「緊急」優先度で即時公開する
- 全社員がダッシュボードまたはお知らせ画面から重要情報を確認する
- 有効期限が切れたお知らせが自動的に一覧から非表示になる

## 3. 業務要件（機能要件）

### 3.1 機能一覧

| ID   | 機能名               | 概要                                                               | 対象ロール |
|------|--------------------|--------------------------------------------------------------------|----------|
| F-AN-01 | お知らせ一覧表示    | 公開中のお知らせを新着順に一覧表示する                              | 全員 |
| F-AN-02 | お知らせフィルタリング | カテゴリ・優先度・公開状態でお知らせを絞り込む                     | 全員（管理者は公開状態も選択可）|
| F-AN-03 | お知らせ作成        | タイトル・本文・カテゴリ・優先度・公開日時・有効期限を設定して作成 | admin, hr |
| F-AN-04 | お知らせ編集        | 既存のお知らせを更新する                                           | admin, hr |
| F-AN-05 | お知らせ削除        | お知らせを削除する（確認ダイアログあり）                           | admin, hr |
| F-AN-06 | 公開/非公開切替     | お知らせの公開状態をワンクリックで切り替える                       | admin, hr |
| F-AN-07 | 下書き管理          | 非公開（下書き）状態のお知らせを管理者が確認・編集できる           | admin, hr |
| F-AN-08 | 有効期限管理        | 有効期限を過ぎたお知らせは公開中一覧から自動除外する（DB RLS）     | 全員 |

### 3.2 機能詳細

#### F-AN-01：お知らせ一覧表示

- 公開中（`is_published = true`）かつ有効期限内（`expires_at IS NULL OR expires_at > NOW()`）の
  お知らせを表示
- 表示順：`published_at` 降順（新着優先）
- 1件ごとに優先度バッジ・カテゴリバッジ・タイトル・公開日・本文プレビュー（最大3行）を表示
- 「緊急」優先度のカードは赤枠で強調表示

#### F-AN-03：お知らせ作成

| 項目 | 型 | 必須 | バリデーション |
|------|----|------|--------------|
| タイトル | TEXT | ○ | 1〜200文字 |
| 本文 | TEXT | ○ | 1文字以上 |
| カテゴリ | ENUM | ○ | general/hr/it/management/other |
| 優先度 | ENUM | ○ | low/normal/high/urgent |
| 公開フラグ | BOOLEAN | ○ | true=即時公開、false=下書き |
| 公開日時 | TIMESTAMPTZ | △ | 公開フラグON時に設定可（未設定時は現在時刻） |
| 有効期限 | TIMESTAMPTZ | - | 公開日時より後であること |

## 4. 非機能要件

| 分類 | 要件 | 目標値 |
|------|------|-------|
| 性能 | お知らせ一覧の表示応答時間 | 2秒以内（通常負荷） |
| 性能 | 作成・更新・削除操作の応答時間 | 3秒以内 |
| セキュリティ | 一般従業員は公開済みのみ参照可（RLS） | ― |
| セキュリティ | 作成・編集・削除は HR/admin のみ（RLS） | ― |
| 可用性 | Supabase SLA に準拠 | 99.9% 以上 |
| 操作性 | 既存 Bootstrap 5 UI と統一されたデザイン | ― |
| 保守性 | Vue Composition API + TypeScript 型安全 | ― |

---

## 5. 制約条件

| 種別 | 内容 |
|------|------|
| 技術 | フロントエンドは Vue 3 + TypeScript、データベースは Supabase（PostgreSQL） |
| 認証 | Supabase Auth の JWT を使用。未認証ユーザーはアクセス不可 |
| ロール制御 | Supabase Row Level Security（RLS）ポリシーで実施 |
| UI | Bootstrap 5 を使用し、既存画面と統一されたデザインとする |
| 予算 | Supabase 無料プラン内で実装する（追加インフラ不要） |

---

## 6. 前提条件・前提システム

| 前提 | 内容 |
|------|------|
| Supabase | `profiles` テーブルに `role` カラムが存在し、RLS の基準として使用可能 |
| 認証システム | Supabase Auth によるメール/パスワード認証が有効 |
| `update_updated_at_column()` 関数 | 001_initial_schema.sql で定義済みのトリガー関数 |
| フロントエンド | Vue Router・Pinia の認証ストア（`useAuthStore`）が実装済み |

---

## 7. スコープ（範囲）

### 対象範囲

- お知らせ CRUD 機能（作成・読取・更新・削除）
- 公開/非公開切替
- カテゴリ・優先度・公開状態によるフィルタリング
- 有効期限管理（DB レベルの RLS による自動除外）
- ロールベースアクセス制御（RLS ポリシー）
- フロントエンド単体テスト（`useAnnouncements` コンポーザブル）

### 除外範囲

- お知らせ作成時の自動メール通知（将来対応）
- プッシュ通知・リアルタイム配信（将来対応：Supabase Realtime 利用を想定）
- お知らせへのコメント・リアクション機能
- お知らせの添付ファイル機能
- 部署別・個人別の配信ターゲット指定

## 8. 用語定義・略語一覧

| 用語 | 定義 |
|------|------|
| お知らせ (Announcement) | HR 担当者・管理者が全社員向けに発信する情報 |
| 公開 (is_published = true) | 全社員が閲覧可能な状態 |
| 下書き (is_published = false) | HR/admin のみ閲覧可能な未公開状態 |
| 有効期限 (expires_at) | この日時を超えると公開一覧から除外される期限 |
| カテゴリ | 情報の分類（全社 / 人事・総務 / IT・システム / 経営 / その他） |
| 優先度 | 情報の緊急度（低 / 通常 / 重要 / 緊急） |
| RLS | Row Level Security。Supabase のテーブル行レベルアクセス制御 |
| HR | Human Resources。人事担当者を指す |
