# 要件定義書 — お知らせ（掲示板）機能

| バージョン | 作成日 | 作成者 |
|---|---|---|
| 1.0 | 2026-03-30 | システムアーキテクト |

---

## 1. 目的・背景

### 1.1 目的

jinij 社内人事システムに **お知らせ（掲示板）機能** を追加し、HR・管理者が全従業員に向けて社内連絡・重要通知・イベント案内を一元配信できる仕組みを提供する。

### 1.2 背景

現状のシステムには従業員向け一斉情報発信の手段がなく、休暇承認時の個人通知（`notifications` テーブル）しか存在しない。メール・チャットツールと分散した情報共有を人事システム内に集約し、情報の見落ちを防ぐ。

---

## 2. 対象ユーザー・利用シーン

| ユーザー種別 | ロール | 利用シーン |
|---|---|---|
| 人事担当者 | `hr` | 健康診断案内・給与改定通知など人事施策の周知 |
| 管理者 | `admin` | システム障害・メンテナンス告知、全社方針の発信 |
| 一般従業員 | `employee` / `manager` | ダッシュボードへのアクセス時に最新のお知らせを確認 |

---

## 3. 業務要件（機能要件）

| ID | 機能名 | 概要 | 対象ロール |
|---|---|---|---|
| F-80 | お知らせ一覧表示 | 公開済みお知らせをカテゴリ・ピン留め順に表示 | 全員 |
| F-81 | お知らせ新規作成 | タイトル・本文・カテゴリ・公開日時・有効期限・ピン留めを登録 | hr / admin |
| F-82 | お知らせ編集 | 既存お知らせの内容・公開設定を変更 | hr / admin |
| F-83 | お知らせ削除 | お知らせを論理削除ではなく物理削除 | hr / admin |
| F-84 | 下書き保存 | `published_at = NULL` として非公開で保存 | hr / admin |
| F-85 | 即時公開 | 下書き状態のお知らせを現在時刻で公開状態に変更 | hr / admin |
| F-86 | カテゴリフィルター | 一般 / 重要 / イベント / 人事 でフィルタリング | 全員 |
| F-87 | 有効期限管理 | `expires_at` を過ぎたお知らせは自動的に一覧から除外 | システム |
| F-88 | ピン留め | 重要なお知らせを一覧の先頭に固定表示 | hr / admin |

---

## 4. 非機能要件

| 分類 | 要件 |
|---|---|
| **性能** | お知らせ一覧表示：1秒以内（p95） |
| **可用性** | 既存システムと同等の 99.5% 稼働率 |
| **セキュリティ** | RLS により従業員は自分以外のデータを直接操作不可。hr/admin のみ書き込み許可 |
| **データ保持** | お知らせは削除操作まで永続保持（論理削除なし） |
| **UI** | 既存 Bootstrap 5 スタイルに準拠。モバイル対応（レスポンシブ） |
| **アクセシビリティ** | Bootstrap の aria 属性を活用し、スクリーンリーダー対応 |

---

## 5. 制約条件

| 区分 | 内容 |
|---|---|
| 技術 | 既存の Supabase（PostgreSQL）・Vue 3 Composition API・Pinia の技術スタック内で実装 |
| DB | Supabase RLS（Row Level Security）を必須適用 |
| UI | 既存ナビゲーション・レイアウトコンポーネントを流用。新規 CSS フレームワーク導入なし |
| 規模 | 想定お知らせ件数：年間 200 件以内 |
| 納期 | 現行 v1.3 マイルストーン内での実装完了 |

---

## 6. 前提条件・前提システム

| 項目 | 内容 |
|---|---|
| 認証基盤 | Supabase Auth（JWT）が稼働済みであること |
| プロファイル | `profiles` テーブルに `role` カラムが存在し、hr/admin が正しく設定済みであること |
| フロントエンド | Node.js 環境で Vue 3 アプリが動作すること |
| Supabase | プロジェクトに DDL 実行権限があること |

---

## 7. スコープ（範囲）

### 対象範囲

- `announcements` テーブルの DDL・RLS 定義
- フロントエンド: 一覧・作成・編集・削除・即時公開画面
- ルーティング `/announcements` 追加
- サイドバーナビゲーションへの追加

### 除外範囲

- お知らせへのコメント・リアクション機能
- プッシュ通知・メール連携（既存 `notifications` システムと別管理）
- お知らせ添付ファイル
- 閲覧者ログ・既読管理

---

## 8. 用語定義・略語一覧

| 用語 | 定義 |
|---|---|
| お知らせ | `announcements` テーブルに格納される掲示情報 |
| 下書き | `published_at = NULL` の非公開状態のお知らせ |
| ピン留め | `is_pinned = true` で一覧先頭に固定されるお知らせ |
| 有効期限 | `expires_at` で指定される掲示終了日時 |
| カテゴリ | `general`（一般）/ `important`（重要）/ `event`（イベント）/ `hr`（人事）の 4 種 |
| RLS | Row Level Security。PostgreSQL の行単位アクセス制御 |
| hr | 人事担当ロール（`role = 'hr'`）|
| admin | 管理者ロール（`role = 'admin'`）|
