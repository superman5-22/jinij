# 結合テスト設計書 — お知らせ（掲示板）機能

| バージョン | 作成日 | 実施者 |
|---|---|---|
| 1.0 | 2026-03-30 | システムアーキテクト |

---

## 1. テスト対象インターフェース・連携機能

| 連携 | 内容 |
|---|---|
| `AnnouncementView.vue` ↔ `useAnnouncements()` | View が composable の state を正しくバインドし、操作に応じた API 呼び出しが行われること |
| `useAnnouncements()` ↔ Supabase JS クライアント | クエリビルダーが正しく組み立てられ、DB に正しい SQL が発行されること |
| `router/index.ts` ↔ `AnnouncementView.vue` | `/announcements` ルートが View を正しくレンダリングすること |
| `AppSidebar.vue` ↔ `router` | サイドバーの「お知らせ」リンクが `/announcements` に遷移すること |
| RLS ↔ Supabase Auth | ロール別のアクセス制御が DB レベルで機能すること |

---

## 2. テスト観点

| 観点 | 内容 |
|---|---|
| データフロー | View → composable → Supabase の各層でデータが正しく受け渡されること |
| UI 反映 | composable の `announcements.value` 変更が View に即時反映されること |
| 権限分岐 | `auth.isHR` フラグに応じてボタン表示/非表示が切り替わること |
| エラー表示 | composable の `error.value` が View のアラートに反映されること |
| ローディング | `isLoading.value` が View のスピナーに反映されること |
| ルーティング | 未認証アクセスがログイン画面にリダイレクトされること |

---

## 3. テスト条件

### 前提条件

- Supabase ローカル環境または Staging 環境が稼働していること
- `008_announcements.sql` マイグレーションが適用済みであること
- テスト用アカウントが存在すること（各ロール 1 件ずつ）

### テストデータ

| No | データ内容 | 状態 |
|---|---|---|
| TD-01 | カテゴリ `general`、公開済み | 正常公開 |
| TD-02 | カテゴリ `important`、ピン留め、公開済み | ピン留め |
| TD-03 | カテゴリ `hr`、下書き（`published_at = NULL`） | 下書き |
| TD-04 | カテゴリ `event`、有効期限切れ | 期限切れ |

---

## 4. テスト手順

### IT-01: 一覧表示とフィルター連携

| ステップ | 操作 | 確認内容 |
|---|---|---|
| 1 | `employee` ロールでログイン | ログイン成功 |
| 2 | サイドバーの「お知らせ」クリック | `/announcements` に遷移 |
| 3 | 画面表示 | TD-01, TD-02 が表示される。TD-03（下書き）・TD-04（期限切れ）は非表示 |
| 4 | ピン留め | TD-02 が先頭に表示される |
| 5 | カテゴリ「重要」を選択 | TD-02 のみ表示 |
| 6 | カテゴリ「全て」に戻す | TD-01, TD-02 が表示 |

### IT-02: HR による作成・公開連携

| ステップ | 操作 | 確認内容 |
|---|---|---|
| 1 | `hr` ロールでログイン | ログイン成功 |
| 2 | 「お知らせ」画面を開く | 「新規作成」ボタンが表示される |
| 3 | 「新規作成」クリック → モーダル表示 | タイトル・本文が空 |
| 4 | タイトル「テスト」、本文「本文」、カテゴリ「一般」、公開日時 = 空 で登録 | 下書きとして保存される |
| 5 | 「下書きを含む」ON | 作成した下書きが一覧に現れる |
| 6 | 下書きカードの「即時公開」ボタン押下 | `published_at` に現在時刻がセットされ、通常一覧に移動 |

### IT-03: 権限による操作ボタン制御

| ステップ | 操作 | 確認内容 |
|---|---|---|
| 1 | `employee` ロールでログイン | — |
| 2 | 「お知らせ」画面表示 | 「新規作成」ボタンなし。カードに編集/削除ボタンなし |
| 3 | `admin` ロールに切り替え | 「新規作成」ボタンあり。カードに全ボタンあり |

### IT-04: 編集・削除連携

| ステップ | 操作 | 確認内容 |
|---|---|---|
| 1 | `hr` ロールでログイン、お知らせ一覧 | — |
| 2 | TD-01 の「編集」ボタン押下 | モーダルが開き、既存値が入力済み |
| 3 | タイトルを変更して「更新」 | 一覧のカードタイトルが更新される |
| 4 | TD-01 の「削除」ボタン押下 | 確認ダイアログが開く |
| 5 | 「削除する」押下 | 一覧から TD-01 が消える |

### IT-05: RLS 権限制御

| ステップ | 操作 | 確認内容 |
|---|---|---|
| 1 | `employee` ロールで直接 Supabase API に INSERT リクエスト | RLS により 403/permission error |
| 2 | `hr` ロールで INSERT | 成功 |
| 3 | `employee` ロールで他ユーザーの下書きを SELECT | 公開済みのみ返却。下書きは取得できない |
