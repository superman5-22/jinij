# 要件定義書 — お知らせ掲示板機能（F-90）

**ドキュメント番号**: jinij-REQ-004
**対象機能**: お知らせ掲示板（Announcement Board）
**バージョン**: 1.0
**作成日**: 2026-03-30

---

## 1. 目的・背景

### 背景

jinij HR システムでは従業員管理・勤怠・給与・休暇申請など基幹 HR 機能が整備されているが、
HR 部門や管理職が社内向けに情報を発信する手段がシステム内に存在しなかった。
現状は社内メール・チャットツール・掲示板への貼り紙などが混在しており、
情報伝達の抜け漏れや受け取り確認の困難さが課題となっている。

### 目的

- HR 部門・管理者が社内アナウンスを jinij 内で一元管理できる仕組みを提供する
- 全従業員が業務に関連した公式情報へアクセスできる掲示板を設ける
- 既読管理によって情報の周知漏れを低減する

## 2. 対象ユーザー・利用シーン

| ユーザー | 役割 | 利用シーン |
|---------|------|-----------|
| HR 担当者（hr）| 作成・編集・削除・公開管理 | 就業規則変更・休暇制度案内・健康診断案内を作成 |
| 管理者（admin） | 作成・編集・削除・公開管理 | システム利用案内・緊急連絡の掲示 |
| マネージャー（manager）| 閲覧・既読 | 部署横断ルール変更・全社イベントの確認 |
| 一般従業員（employee） | 閲覧・既読 | 日常業務に関わるお知らせの確認 |

## 4. 非機能要件

| 区分 | 要件 | 基準値 |
|------|------|--------|
| **性能** | お知らせ一覧表示レスポンス | 通常時 1 秒以内 |
| **性能** | 同時接続ユーザー数 | 既存 HR システムと同等（最大 200 同時） |
| **セキュリティ** | データアクセス制御 | Supabase RLS により、未ログインユーザーはアクセス不可 |
| **セキュリティ** | 権限制御 | 一般従業員・マネージャーは閲覧専用（作成・編集・削除不可） |
| **可用性** | サービス継続率 | 既存システムと同等（Supabase SLA に準拠） |
| **運用性** | 有効期限切れお知らせ | DB レベルで自動非表示（アプリ側フィルタ + RLS） |
| **ユーザビリティ** | 既存 UI との統一 | Bootstrap 5 + 既存デザイントークンに準拠 |
| **保守性** | テストカバレッジ | Composable の主要関数に Vitest ユニットテストを整備 |

---

## 5. 制約条件

| 区分 | 内容 |
|------|------|
| 技術制約 | フロントエンドは Vue 3 / TypeScript、バックエンド DB は Supabase (PostgreSQL) に統一 |
| 権限制約 | Supabase RLS ポリシーによる DB レベルアクセス制御が必須 |
| UI 制約 | 既存アプリのデザインシステム（Bootstrap 5 + CSS カスタムプロパティ）を踏襲 |
| スコープ制約 | メール通知・プッシュ通知は本フェーズの対象外（通知ベルへの連携も除外） |
| 予算・工数 | 本機能は既存システムへの追加機能であり、既存コンポーネント・Composable パターンを最大限再利用 |

## 6. 前提条件・前提システム

| 項目 | 内容 |
|------|------|
| 認証基盤 | Supabase Auth（既存）によるユーザー認証・JWT 発行が前提 |
| プロファイルテーブル | `profiles` テーブルに `role` カラム（employee / manager / hr / admin）が存在すること |
| `update_updated_at_column` 関数 | 既存マイグレーションで作成済みのトリガー関数 |
| フロントエンド環境 | Vue 3 + Pinia（useAuthStore）+ Vue Router が導入済みであること |
| Supabase クライアント | `@/lib/supabase` に初期化済みクライアントがエクスポートされていること |

## 7. スコープ（範囲）

### 対象範囲

- お知らせデータの CRUD（作成・閲覧・更新・削除）
- カテゴリ分類・ピン留め・有効期限
- 既読管理（announcement_reads テーブル）
- キーワード検索・カテゴリフィルター
- 下書き機能（公開日時 NULL）
- HR / admin 向け管理 UI（作成・編集・削除モーダル）
- DB マイグレーション（007_announcements.sql）
- フロントエンド単体テスト（useAnnouncements.test.ts）

### 除外範囲

- 通知ベル・メール等へのリアルタイム通知連携
- 添付ファイル・画像のアップロード
- お知らせへのコメント・リアクション機能
- 既読率レポート・集計機能
- 承認ワークフロー（下書き → 承認者 → 公開）

## 8. 用語定義・略語一覧

| 用語 | 定義 |
|------|------|
| お知らせ（Announcement） | HR 部門・管理者が全従業員向けに発信する社内情報 |
| 下書き（Draft） | `published_at` が NULL のお知らせ。HR/admin のみ参照可能 |
| 公開（Published） | `published_at <= NOW()` かつ `expires_at IS NULL OR expires_at > NOW()` の状態 |
| ピン留め（Pinned） | 一覧上部に固定表示されるお知らせ（`is_pinned = TRUE`） |
| 有効期限（Expires At） | 指定日時を過ぎると自動的に非表示になる設定 |
| 既読（Read） | `announcement_reads` テーブルにレコードが存在する状態 |
| カテゴリ | 一般 / 人事 / イベント / 緊急 の 4 種別 |
| RLS | Row Level Security。Supabase (PostgreSQL) の行単位アクセス制御機能 |
| HR | Human Resources（人事担当ロール） |
