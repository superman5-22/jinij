## 3. 業務シナリオテスト

### ST-01: 評価管理 完全ワークフロー（正常系）

**シナリオ概要**: manager が従業員の評価を登録し、hr が確定するまでの一連のフロー

| ステップ | 操作者 | 操作内容 | 期待結果 |
|---|---|---|---|
| 1 | manager | `/evaluations` を開く | 「人事評価管理」画面が表示される |
| 2 | manager | 「新規評価登録」ボタン押下 | モーダルが開く |
| 3 | manager | 田中太郎 / 2026年 / Q1 / 全スコア3〜5 / コメント入力 | フォームに値が設定される |
| 4 | manager | フォームプレビューの総合スコアを確認 | `(スコア合計 / 5)` の小数値が表示される |
| 5 | manager | 「登録」ボタン押下 | モーダルが閉じ、テーブルに新規行が追加される（status=下書き） |
| 6 | manager | 「提出」ボタン（送信アイコン）押下 → 確認OK | status が「提出済み」に変わる |
| 7 | hr | 同画面を再度読み込み | 田中太郎の評価が「提出済み」で表示される |
| 8 | hr | 「確定」ボタン（チェックアイコン）押下 → 確認OK | status が「確定」に変わる |
| 9 | hr | 編集・削除ボタンの状態確認 | 両ボタンが disabled になっている |
| 10 | employee（田中太郎） | `/evaluations` を開く（ガードにより不可） | ダッシュボードにリダイレクト |

**合否判定**: ステップ 1〜10 全て期待結果と一致すること

## 4. 合否判定基準

| 重大度 | 定義 | 合否への影響 |
|---|---|---|
| Critical | データ消失・不正アクセス・認証バイパス | 1件でも発生 → 不合格 |
| High | 機能が動作しない・業務フローが完結しない | 未解決のまま 0件 → 合格 |
| Medium | 表示崩れ・軽微な動作不良 | 既知課題として管理し合格可 |
| Low | 改善要望・使いやすさの問題 | 合否に影響しない |

**合格条件**: Critical / High の未解決課題が 0件であること
