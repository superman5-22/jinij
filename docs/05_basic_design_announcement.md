## 2. 機能一覧

### 機能階層図

```
F-90 お知らせ掲示板
├── F-90-01 ～ F-90-03  閲覧系（全ロール）
│   ├── F-90-01 一覧表示
│   ├── F-90-02 詳細表示
│   ├── F-90-10 キーワード検索
│   ├── F-90-11 カテゴリフィルター
│   ├── F-90-12 既読登録
│   └── F-90-13 未読バッジ表示
└── F-90-04 ～ F-90-09  管理系（hr / admin のみ）
    ├── F-90-03 作成
    ├── F-90-04 編集
    ├── F-90-05 削除
    ├── F-90-06 下書き保存
    ├── F-90-07 カテゴリ設定
    ├── F-90-08 ピン留め
    ├── F-90-09 有効期限設定
    └── F-90-14 下書き含む全件表示
```

| 機能 ID | 機能名 | 処理概要 |
|---------|--------|---------|
| F-90-01 | 一覧表示 | ピン留め順・公開日時降順でリスト表示。ページネーションなし（最大 50 件） |
| F-90-02 | 詳細表示 | カード クリックでモーダル表示。本文全文を改行保持で表示 |
| F-90-03 | 作成 | フォームモーダルから作成。公開日時省略で下書き |
| F-90-04 | 編集 | 既存データをフォームに展開して上書き保存 |
| F-90-05 | 削除 | 確認モーダル後に物理削除 |
| F-90-06 | 下書き | `published_at = NULL` として保存 |
| F-90-07 | カテゴリ | general / hr / event / urgent の 4 種 |
| F-90-08 | ピン留め | `is_pinned = TRUE` でリスト最上位に表示 |
| F-90-09 | 有効期限 | `expires_at` を過ぎると RLS + アプリ両方で非表示 |
| F-90-10 | 検索 | `title.ilike` + `body.ilike` の OR 条件（300ms debounce） |
| F-90-11 | フィルター | カテゴリ select で即時絞り込み |
| F-90-12 | 既読登録 | 詳細モーダル開示時に `announcement_reads` へ upsert |
| F-90-13 | 未読バッジ | `is_read = false` かつ `published_at IS NOT NULL` に「NEW」バッジ |
| F-90-14 | 全件表示 | HR/admin がトグルで下書き含む全件を参照 |

## 5. バッチ処理一覧

| バッチ ID | 処理名 | 処理概要 | 実行タイミング |
|-----------|--------|---------|--------------|
| BAT-90-01 | 有効期限切れ非表示 | `expires_at < NOW()` のレコードは RLS + アプリ WHERE で自動除外 | リクエスト都度（バッチ不要） |

> 有効期限切れお知らせの物理削除は要件外。論理的非表示（フィルタ）のみ対応。

## 6. 外部インターフェース設計

### Supabase PostgREST API

| 操作 | HTTP メソッド | エンドポイント | 認証 |
|------|-------------|--------------|------|
| 一覧取得 | GET | `/rest/v1/announcements?select=*,...&order=...` | Bearer JWT |
| 単件作成 | POST | `/rest/v1/announcements` | Bearer JWT |
| 単件更新 | PATCH | `/rest/v1/announcements?id=eq.{id}` | Bearer JWT |
| 単件削除 | DELETE | `/rest/v1/announcements?id=eq.{id}` | Bearer JWT |
| 既読一覧 | GET | `/rest/v1/announcement_reads?announcement_id=in.(...)` | Bearer JWT |
| 既読登録 | POST (upsert) | `/rest/v1/announcement_reads` | Bearer JWT |

> supabase-js クライアントがリクエスト構築を抽象化するため、アプリコードは直接 HTTP を記述しない。

## 7. データベース概要設計

### 主要エンティティ

```
announcements
─────────────
id           (PK)
title
body
category     (general | hr | event | urgent)
is_pinned
published_at (NULL = 下書き)
expires_at   (NULL = 無期限)
created_by   (FK → auth.users)

──────────────────
announcement_id  (PK, FK → announcements)

```

### ER 図（概要）

```
auth.users ─┬──< announcements (created_by)
            └──< announcement_reads (user_id)
                       │
                    announcements ──< announcement_reads (announcement_id)
```

## 8. 非機能要件に対する基本方針

| 非機能要件 | 実現方式 |
|-----------|---------|
| **性能** | 公開日時・カテゴリ・ピン留めにインデックスを設置。一覧は最大 50 件で制限 |
| **セキュリティ** | Supabase RLS による DB レベル制御 + Vue Router ガードによる画面レベル制御 |
| **セキュリティ (XSS)** | `v-html` 不使用。本文は `white-space: pre-wrap` でテキスト表示 |
| **可用性** | Supabase マネージドサービスの SLA に依存（既存システムと同等） |
| **運用性** | 有効期限切れは RLS で自動除外。物理削除バッチ不要 |
| **保守性** | 既存 Composable パターン・モーダルデザインに統一。テスト 16 ケース整備済み |
